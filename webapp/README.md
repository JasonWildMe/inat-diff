# iNaturalist Invasives Monitor - Web Application

A web service that delivers automated invasive species detection reports to biologists via email.

## Features

- **Simple subscription form** - Biologists enter their email and region
- **Email verification** - Double opt-in to prevent spam
- **Automated scheduling** - Monthly or weekly reports via Celery Beat
- **Inline HTML reports** - Reports display directly in email
- **Admin dashboard** - Monitor subscriptions and trigger reports
- **Magic link authentication** - No passwords to remember

## Architecture

```
User → Nginx → FastAPI → Celery → iNaturalist API
                  ↓
                Redis
                  ↓
              Mandrill → Email
```

## Quick Start (Development)

### Prerequisites

- Python 3.10+
- Redis server
- Mandrill API key

### Setup

```bash
# Clone repository
git clone https://github.com/YOUR_USERNAME/inat-diff.git
cd inat-diff

# Create virtual environment
python -m venv venv
source venv/bin/activate  # Linux/Mac
# or: venv\Scripts\activate  # Windows

# Install packages
pip install -e .
pip install -r webapp/requirements.txt

# Start Redis (in another terminal)
redis-server

# Set environment variables
export MANDRILL_API_KEY=your_key_here
export SECRET_KEY=dev-secret-key
export BASE_URL=http://localhost:8000

# Initialize database
python -c "from webapp.models import init_db; init_db()"

# Start web server
uvicorn webapp.main:app --reload

# Start Celery worker (in another terminal)
celery -A webapp.tasks worker --loglevel=info

# Start Celery beat scheduler (in another terminal)
celery -A webapp.tasks beat --loglevel=info
```

Visit http://localhost:8000 to see the application.

## Production Deployment (Ubuntu)

### 1. Provision Azure VM

- Create Ubuntu 22.04 or 24.04 VM
- Minimum specs: 2 vCPU, 4GB RAM (reports can be memory-intensive)
- Open ports 80 and 443

### 2. Configure DNS

Point `invasives.wildme.org` to your server's IP address.

### 3. Run Installation Script

```bash
# SSH to your server
ssh root@your-server-ip

# Download and run install script
curl -O https://raw.githubusercontent.com/YOUR_USERNAME/inat-diff/main/webapp/deploy/install.sh
chmod +x install.sh
./install.sh
```

### 4. Configure Environment

```bash
# Edit environment file
nano /opt/invasives/.env
```

Set these values:
- `MANDRILL_API_KEY` - Your Mandrill API key
- `SECRET_KEY` - A random string (generated by script)
- `BASE_URL` - https://invasives.wildme.org
- `FROM_EMAIL` - Your sending email address

### 5. Set Up SSL

```bash
certbot --nginx -d invasives.wildme.org
```

### 6. Start Services

```bash
systemctl start redis-server
systemctl start invasives-web
systemctl start invasives-worker
systemctl start invasives-beat
systemctl restart nginx
```

### 7. Verify Installation

```bash
# Check services
systemctl status invasives-web
systemctl status invasives-worker
systemctl status invasives-beat

# Check logs
journalctl -u invasives-web -f
journalctl -u invasives-worker -f

# Test health endpoint
curl http://localhost:8000/health
```

Visit https://invasives.wildme.org to verify the application is running.

## Configuration Reference

### Environment Variables

| Variable | Description | Default |
|----------|-------------|---------|
| `MANDRILL_API_KEY` | Mandrill API key for emails | Required |
| `SECRET_KEY` | Application secret key | Required |
| `BASE_URL` | Public URL of the application | https://invasives.wildme.org |
| `FROM_EMAIL` | Email sender address | reports@invasives.wildme.org |
| `FROM_NAME` | Email sender name | iNaturalist Invasives Monitor |
| `DATABASE_URL` | Database connection URL | sqlite:///webapp/invasives.db |
| `REDIS_URL` | Redis connection URL | redis://localhost:6379/0 |

### Scheduled Tasks

- **Monthly reports**: 1st of each month at 6:00 AM UTC
- **Weekly reports**: Every Monday at 6:00 AM UTC

To modify the schedule, edit `webapp/celery_config.py`.

## Administration

### Admin User Management

The admin dashboard requires HTTP Basic Authentication. Manage admin users with the CLI:

```bash
# Create an admin user (required before first login)
python -m webapp.manage create-admin admin secretpassword

# List all admin users
python -m webapp.manage list-admins

# Reset a password
python -m webapp.manage reset-password admin newpassword

# Delete an admin user
python -m webapp.manage delete-admin oldadmin
```

### Admin Dashboard

Visit `/admin` to access the admin dashboard. You'll be prompted for username/password.

Features:
- View subscription statistics
- See recent subscriptions and reports
- Manually trigger report generation
- Monitor failed reports

### Manual Report Generation

```bash
# Via curl with authentication
curl -u admin:password -X POST http://localhost:8000/admin/trigger-reports/monthly

# Or trigger for specific subscription
curl -u admin:password -X POST http://localhost:8000/admin/generate-report/1
```

### Database Management

```bash
# Access SQLite database
sqlite3 /opt/invasives/inat-diff/webapp/invasives.db

# View subscriptions
SELECT * FROM subscriptions;

# View reports
SELECT * FROM reports ORDER BY created_at DESC LIMIT 10;
```

## Troubleshooting

### Reports Not Generating

1. Check Celery worker is running: `systemctl status invasives-worker`
2. Check Redis is running: `systemctl status redis-server`
3. Check worker logs: `journalctl -u invasives-worker -f`
4. Verify iNaturalist API is accessible

### Emails Not Sending

1. Verify `MANDRILL_API_KEY` is set correctly
2. Check Mandrill dashboard for bounces/errors
3. Verify FROM_EMAIL is verified in Mandrill
4. Check worker logs for email errors

### Slow Report Generation

Reports for large regions (like Oregon) can take 30-120 minutes due to:
- 20 years of historical data comparison
- Rate limiting to respect iNaturalist API

This is normal behavior.

### Database Issues

```bash
# Backup database
cp /opt/invasives/inat-diff/webapp/invasives.db /opt/invasives/backups/

# Reset database (WARNING: deletes all data)
rm /opt/invasives/inat-diff/webapp/invasives.db
python -c "from webapp.models import init_db; init_db()"
```

## Security Considerations

- Admin dashboard uses HTTP Basic Authentication
  - Create admin users with: `python -m webapp.manage create-admin`
  - Passwords are hashed with bcrypt (12 rounds)
  - Failed login attempts are logged for security monitoring
- CSRF protection on all forms (signed tokens, 1-hour expiry)
- Rate limiting: 10 subscription attempts per hour per IP
- Email validation before accepting subscriptions
- Path traversal protection on report file serving
- Security headers on all responses (X-Frame-Options, X-Content-Type-Options, etc.)
- Magic links expire after 48 hours
- Unsubscribe tokens are long-lived (1 year)
- Database contains email addresses - secure appropriately
- Always use HTTPS in production (certbot handles this)
